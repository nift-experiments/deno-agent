The browser proxy changes only the Orama SDK transport to known local results/empty/error responses, with POST disabled. It does not change the preserved publication. Remote search relevance, deployment credentials, analytics and feedback are outside local parity; production frontend assets must still match the pinned reference. No feedback, telemetry or search uploads were sent. HTTP fixtures use the original server directly; the test proxy follows redirects and therefore is not evidence of redirect status.

The full semantic contract outside the repos covers every HTML route's metadata, canonical, structured data, headings and IDs. It records 47 duplicate-ID routes, 221 potential unresolved local links and 2,671 potential unresolved fragments. These are baseline observations, not 2,892 newly introduced migration defects: runtime/wildcard redirects can resolve some paths and generated references already emit warnings. ## Input and renderer boundaries

The pinned config actually uses MarkdownIt for ordinary `.md` and MDX only for three `.mdx` files. Upstream README/AGENTS prose describes broader MDX handling; the executable pinned config and observed source-route mapping govern this experiment. Required Markdown behavior includes default attrs/definition lists, replacements, admonitions, copy buttons, fence titles, relative links, heading anchors and Prism. JSX is required for shared layouts, lint/examples and grouped references. We will use pinned standalone render libraries and bounded actual source behavior, without constructing a Lume Site in routine migration builds.

Frozen prepared generated inputs are authoritative for initial parity. The first and prepared acquisitions are both retained: 41 standard-library Markdown files differ by a removed blank line in a custom section, with unchanged HTML. Network acquisition and timestamps are disclosed, not silently normalized into benchmark inputs. Generated inputs, local search inputs, reference CSS/JS, OG images, downloads and llms outputs remain explicitly inventoried. Dependency installation is outside publication timing. Full fresh-application tests must make their generated-input/cache boundary visible.
