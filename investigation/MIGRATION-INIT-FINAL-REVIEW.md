# Final `nift init --migration` review

The generated AGENTS/MIGRATION/HANDOVER material was useful in this production-scale migration. Its strongest rules—reproduce upstream, preserve parity, prefer bounded compatibility, do not change Nift, commit checkpoints, retain differences and verify fresh checkouts—remained actionable. Init supplies a workbook, not a converter. No Nift implementation change was made during this review.

D0–D6 findings remain in `MIGRATION-INIT-REVIEW.md`; the original generated files remain under `generated-init/`. This final assessment adds concrete gaps exposed by profiling and source maintenance.

| Target generated artifact | Suggested addition | Evidence from this campaign |
|---|---|---|
| README/HANDOVER command block | Name the **complete project publication command**, renderer refresh command and composition-only command separately. Explain that `nift status` validates tracked composition state, not arbitrary external renderer inputs. | Python orchestrates maintained-source rendering, Nift and ancillary exports; running Nift alone cannot refresh Markdown-derived content. |
| MIGRATION source ownership table | For each family, record authoritative maintained source, derived artifacts, refresh owner/command, normal-build inclusion and deletion behavior. Do not impose upstream's internal generation model on static migrated assets. | All 834 OG images are maintained assets; intentional image maintenance is outside normal publication. Prepared API/std inputs have separate acquisition ownership. |
| `investigation/DEPENDENCIES.json` example | Show derived-cache inputs and output hashes; include missing/corrupt output recovery, renderer/tool identity and shared-query invalidation. Make forced recomputation and fresh application state explicit. | Page caches, ancillary redirect/OG metadata caches and search/LLM caches require verified dependencies, not a hidden benchmark cache. |
| Parity checklist | Test **removal** as well as editing of frontmatter/metadata; test stale route/download/search/alias retirement; compare changed publication with forced recomputation. | Bootstrap metadata initially hid deleted source fields; explicit field ownership fixes it. Twenty maintenance cases and corruption/removal probes test real source behaviors. Removing the actual 404 MDX layout was also checked against unchanged native Lume behavior. |
| Benchmark template | Separate normal cached publication, forced full recomputation, application-cold state, prepared dependencies and upstream acquisition. Keep initial and optimized results. Require five serialized samples, ranges and version/revision records. | Static OG correction, source caching and parallel DOM normalization substantially change costs. Cached publication must not be presented as full rendering. |
| Profile template | Use nested counters and identify overlap, parallel job work and the critical wall-time path. Record process startup and worker lifetime, plus time–memory tradeoffs. | Prism/MDX were small; serial DOM normalization and repeated shared work dominated. Persistent DOM-only workers lower time and increase RSS. |
| Memory template | Label maximum measured process/phase RSS; never call it aggregate process-tree memory without measuring that quantity. | Deno workers are threads in one measured process; separately spawned processes are not summed. |
| Maintained HTML guidance | Make search, downloadable Markdown, LLM projections and route metadata ownership explicit. A source hash acknowledgement is not a semantic consistency proof. | Agent publication is simple but editing a page can require coordinated maintenance of several outputs. |
| Remote behavior ledger | Identify live services, credentials, read-only fixtures and mock transport boundaries. | Local search payload/UX were verified without uploading to upstream Orama; analytics/feedback were not sent. |
| Init rerun documentation | State safe refusal on an existing Nift project; consider an explicit non-destructive guidance-refresh command later. Do not replace project files to refresh instructions. | Existing-project rerun failed safely with unchanged hashes; existing AGENTS content was preserved during first init. |

The dependency template should also distinguish cached module graphs from runtime dependency fetches. The native runner needed exact pinned WASM delivery because Deno graph preparation does not eliminate runtime CDN requests; compilation and worker startup must stay inside the measured phase. This is benchmark tooling guidance, not a migration core requirement.

Suggested concise operating wording:

> Keep maintained source, external prepared inputs, derived caches and publication output distinct. Record their owners and refresh commands. Before optimizing, prove a faithful publication; after optimizing, test source edits, metadata removal, route retirement, cache corruption and fresh-checkout reproduction. Report cached, forced and fresh costs separately, and preserve remaining weaknesses as future work.

These are later Nift planning candidates, separate from the accepted migration architecture. They do not reopen Nift core work or require a general Lume implementation.

Starting again with only generated AGENTS/HANDOVER would give a sound operating discipline, but would **not be sufficient as the sole migration specification**. The agent would still have to inspect executable upstream configuration, identify prepared inputs and services, and create the concrete evidence/ownership/dependency files listed above. The missing pieces should be generated as fill-in scaffolds, not fabricated answers.

Unclear instructions: clarify initialization-before-baseline and composition-only status. Missing instructions: metadata removal, static-asset versus generated-product ownership, ancillary projection transactions, cache corruption and remote boundaries. Missing files/data: baseline manifest, dependency/ownership inventory, divergence ledger, checkpoint table and benchmark sample schema. Poor defaults: placeholder output should be explicitly excluded from publication counts; the generated whitespace-only line should be cleaned in future init work; do not default every upstream generated asset to routine regeneration. Useful rules to retain: parity-first baseline, bounded adapters, frozen core, checkpoints, handover and fresh reproduction. Unnecessary instructions: none of the parity or baseline-preservation rules became unnecessary; long generic Nift usage material could link to canonical docs once a project's actual commands are recorded. Suggested automation: scaffold real-file manifests, compare owned-output retirement, collect serialized phase timings and detect missing evidence. Source-model differences: authored models need renderer dependencies and field deletion ownership; rendered models need explicit projection coordination. Potential CLI work: an opt-in non-destructive guidance refresh and selectable source-model field, separate from any automatic site conversion.
